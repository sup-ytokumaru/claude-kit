# verify

「完了した」「直った」「通った」と**主張する前に**、それを裏づける検証コマンドを実行し、出力を証跡として示す規律。

**位置づけ**: 単独のフェーズではなく、他スキルの出口に掛かるゲート。`/implement` の各ステップ、`/test` の完了報告、`/review` の指摘解消、`/commit`・`/pr` の直前に適用する。ユーザーが明示的に起動してもよい。

**コア原則: 主張の前に証跡。この応答内で実行していない検証は、通ったものとして扱わない。**

## 鉄則

```
新しい検証の証跡がないまま、完了を主張しない
```

「さっき通った」「たぶん大丈夫」は証跡ではない。検証したのは**あのときのツリー**であって、いま統合しようとしているツリーではない。

## ゲート手順

状態を報告する前、または満足を表明する前に、必ずこの順で通す。

1. **特定する** — その主張を証明できるコマンドは何か
2. **実行する** — 部分実行や絞り込みではなく、完全な形で新たに走らせる
3. **読む** — 出力全体・終了コード・失敗件数を確認する
4. **照合する** — 出力は主張を裏づけているか
   - 裏づけていない → 証跡を添えて**実際の状態**を報告する
   - 裏づけている → 証跡を添えて主張する
5. **そのあとで**主張する

途中を飛ばした時点で、それは検証ではなく推測になる。

## 主張と必要な証跡

| 主張 | 必要な証跡 | 不十分なもの |
|---|---|---|
| テストが通る | テストコマンドの出力（失敗 0 件） | 前回の実行結果・「通るはず」 |
| lint が綺麗 | lint の出力（エラー 0 件） | 一部ファイルだけの確認 |
| ビルドが通る | ビルドコマンドの終了コード 0 | lint が通ったこと |
| バグが直った | 元の症状を再現する手順が通ること | コードを直したこと |
| リグレッションテストが効く | 修正を戻すと**赤になる**ことの確認 | テストが一度通ったこと |
| 型が通る | 型チェックの出力（エラー 0 件） | エディタ上で赤線が無いこと |
| エージェントが完了した | 差分（`git diff`）に変更が現れていること | エージェントの成功報告 |
| 要件を満たした | 要件を1行ずつ突き合わせたチェックリスト | テストが通っていること |
| 移行データが一致した | `/migrate-verify` の突合結果 | 件数だけの一致 |

## Red Flags — STOP

- 「〜のはず」「おそらく」「〜と思われる」で状態を語ろうとしている
- 検証の前に「完了しました」「問題ありません」と書こうとしている
- 検証せずに `/commit`・`/pr` へ進もうとしている
- サブエージェントの成功報告をそのまま結論にしている
- 一部だけ確認して全体を推定している
- 「今回だけは省いてよい」と考えている
- 長い作業の終盤で、早く終わらせたくなっている

## 言い訳と現実

| 言い訳 | 現実 |
|---|---|
| 「もう動くはず」 | 実行して確かめる |
| 「確信がある」 | 確信は証跡ではない |
| 「今回だけ」 | 例外を作らない |
| 「lint が通った」 | lint はコンパイルも型も見ていない |
| 「エージェントが成功と言った」 | 差分を自分で確認する |
| 「さっきのセッションで通った」 | いまのツリーで通した証跡が要る |
| 「部分的に見たので十分」 | 部分は全体を証明しない |
| 「言い回しを変えれば主張ではない」 | 完了を示唆する表現はすべて対象 |

## 報告の書き方

証跡は、読み手が再実行できる形で示す。

```
✅ 良い例
  $ bun test
  162 pass / 0 fail
  → 既存テストにリグレッションなし

❌ 悪い例
  テストは問題なく通っています
```

失敗している場合も同じ形式で、隠さず報告する。**未達のまま完了扱いにしない**。原因調査が要るなら `/debug` へ渡す。

## 非対話実行時

検証コマンドの実行はこのスキルの本務であり、起動自体を承認とみなして実行してよい。ただし次を守る。

- 検証が赤だった場合、非対話でも「通った」と報告しない。赤の内容をそのまま報告して停止する
- プロジェクトの検証コマンドが不明な場合は推測で走らせず、`package.json` の scripts・CI 設定・CLAUDE.md から特定する。特定できなければ「検証手段が不明」として報告する
- 実行に時間や課金を伴うコマンド（E2E・デプロイを含むもの）は非対話では実行せず、必要な検証として列挙するにとどめる

## 完了条件

主張しようとしている内容のすべてに、この応答内で実行した検証の証跡が対応している状態。証跡を欠く主張が残っている場合は、その主張を取り下げるか、検証を実行してから報告する。
