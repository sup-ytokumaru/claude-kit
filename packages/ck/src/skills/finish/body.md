# finish

作業ブランチを**片付けて終える**スキル。統合方法をユーザーに選ばせ、選ばれた出口を実行し、使い終わった worktree とブランチを回収する。

**位置づけ**: `/pr` の後段。PR がマージされたあとの回収、および PR を作らずローカルで統合して終える場合の出口を担う。`/commit` までで履歴は整っている前提で、ここでは統合と後始末だけを扱う。

**コア原則: 緑を確かめてから統合し、統合を確かめてから片付ける。どこにも存在しないものを消さない。**

## Step 1: 統合できる状態か確かめる

```bash
git status --short        # 未コミット変更が無いこと
git log --oneline -5      # 何を統合しようとしているか
```

- 未コミット変更があれば `/commit` に戻す（統合前に履歴へ入れる）
- プロジェクトのテストスイートを**いま実行する**。過去に緑だった記録は証跡にならない（`/verify`）
- 赤があれば統合せず、失敗内容を報告して停止する。選択肢の提示は緑になってから

## Step 2: 作業環境を判定する

```bash
GIT_DIR=$(cd "$(git rev-parse --git-dir)" && pwd -P)
GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" && pwd -P)
WORKTREE_PATH=$(git rev-parse --show-toplevel)   # Step 5 で移動する前に控える
```

| 状態 | 出口 | 片付け |
|---|---|---|
| `GIT_DIR` = `GIT_COMMON`（通常のリポジトリ） | 3 択 | worktree の回収は不要 |
| 異なる・名前付きブランチ（worktree） | 3 択 | 出自に応じて回収（Step 6） |
| 異なる・detached HEAD | 2 択（ローカルマージは出さない） | 外部管理のため触らない |

## Step 3: ベース（統合先）ブランチを確定する

分岐元は plans の記録・会話・upstream から特定する。不明なら**推測で進めず確認する**。

> このブランチは `<推定したブランチ>` から分岐しているという理解で合っていますか？

統合先を誤ったマージは取り消しが高くつく。マージ前に必ず確定させる。

## Step 4: 出口を選ばせる

`AskUserQuestion` で提示する。統合するかどうかはユーザーの判断であり、こちらで決めない。

**通常のリポジトリ / 名前付きブランチの worktree（3 択）:**

1. `<base>` にローカルでマージする
2. push して PR を作る（→ `/pr` に渡す）
3. ブランチをこのまま残す

**detached HEAD（2 択）:**

1. 新しいブランチとして push して PR を作る（→ `/pr`）
2. このまま残す

**破棄（ブランチとコミットを捨てる）は選択肢に含めない。** ユーザーが明示的に破棄を求めたときだけ、後述の手順で扱う。

## Step 5: 選ばれた出口を実行する

### 1. ローカルマージ

```bash
MAIN_ROOT=$(git -C "$(git rev-parse --git-common-dir)/.." rev-parse --show-toplevel)
cd "$MAIN_ROOT"
git switch <base>
git pull
git merge <feature-branch>
```

マージ**結果**でテストを流す。ここで赤になったら片付けに進まず、worktree もブランチも残したまま調査する（push していないのでローカルで回復できる）。緑なら Step 6 で worktree を回収し、最後にブランチを削除する。

```bash
git branch -d <feature-branch>    # -D は使わない（未マージを黙って消さないため）
```

### 2. push して PR を作る

push と PR 作成は `/pr` の責務。**worktree はここで消さない**。PR のレビュー指摘はその作業コピーで直すため、マージされるまで残す。

### 3. そのまま残す

現在のブランチ名と worktree のパスを報告して終える。

### 破棄を明示的に求められた場合

消える対象を列挙し、確認を取ってから実行する。

```
以下を完全に削除します（復元できません）:
- ブランチ <name>
- コミット <一覧>
- worktree <path>
```

承認後、メインのリポジトリルートへ移動してから Step 6 の回収を行い、`git branch -D <feature-branch>` で削除する。

## Step 6: worktree を回収する

**ローカルマージと、承認された破棄のときだけ実行する。** PR 作成とブランチ維持では常に残す。worktree の外（メインのリポジトリルート）から実行する。

- `GIT_DIR` = `GIT_COMMON` の場合: worktree は無い。何もしない
- `WORKTREE_PATH` が `.worktrees/` 配下など**こちらで作った作業コピー**の場合: 回収する

```bash
git worktree remove "$WORKTREE_PATH"
git worktree prune
```

- それ以外（ホスト環境が管理する作業コピー）: 触らずそのまま残す

**削除が拒否された場合**（`contains modified or untracked files`）、その worktree にしか存在しないファイルがある。**自分の判断で `--force` を使わない。** 中身を見せて選ばせる。

```bash
git -C "$WORKTREE_PATH" status --porcelain -uall
```

> 未コミットのファイルが残っているため回収できません:
> 1. ブランチにコミットしてから回収する
> 2. メインのリポジトリに移す
> 3. 削除する（復元不可）

## 言い訳と現実

| 言い訳 | 現実 |
|---|---|
| 「さっきテストが通った」 | 統合しようとしているツリーで走らせる |
| 「どう見てもマージしたいはず」 | 統合の判断はユーザーのもの。選択肢を出して待つ |
| 「もう使わなそうなので破棄を提案する」 | 破棄は明示的に求められたときだけ |
| 「PR を出したので worktree は不要」 | 指摘対応をそこで行う。マージされるまで残す |
| 「他の worktree も古そうだから消す」 | 回収するのは自分で作ったものだけ |
| 「拒否されたので --force で消す」 | 拒否はそこにしか無いファイルがある証拠 |
| 「マージ後の失敗はたぶん不安定なテスト」 | 赤なら止める。ブランチも worktree も残す |
| 「ベースは main に決まっている」 | 分岐元を確認する |
| 「push が弾かれたので force push する」 | リモートが進んでいる。調査する。force push はユーザーの明示的な指示があるときだけ |

## 非対話実行時

**マージ・ブランチ削除・worktree 回収・破棄は非対話で実行しない。** いずれも取り消しが難しい、または外向きの操作であるため、Step 1〜3（検証・環境判定・ベースブランチの推定）まで進め、推奨する出口と実行予定のコマンドを提示して停止する。最終判断は人間に残す。

テストが赤だった場合は、非対話でも統合を提案せず、失敗内容をそのまま報告する。

## 完了条件

選ばれた出口が実行され、その結果が検証された状態。

- ローカルマージ: マージ後のテストが緑で、worktree を回収し、ブランチを削除した状態
- PR 作成: `/pr` が URL を報告し、worktree とブランチが残っている状態
- 維持: ブランチ名と worktree のパスを報告した状態
